# 兼容性规则

## 版本原则

- 新增可选字段属于向后兼容改动。
- 删除字段、修改字段类型、改变枚举含义属于破坏性改动。
- 客户端必须忽略尚不认识的服务端响应字段。
- 服务端在协议迁移期应继续接受上一正式客户端版本发送的字段。

## 时间和标识

- 网络传输时间统一使用 UTC ISO 8601 字符串。
- 客户端展示时转换为任务的 IANA 时区，缺省为 `Asia/Shanghai`。
- 任务、设备和账户使用 UUID；本地旧数字 ID 不进入同步协议。
- `revision=0` 只表示尚未上传的新本地任务，服务端持久化任务从 1 开始。

## 删除

已同步任务使用删除墓碑传播。尚未上传且 revision 为 0 的任务在本地直接移除，不发送 delete mutation。

## 增量拉取

`sync/pull` 返回游标之后每个任务的最新状态，不保证提供该任务的每次中间编辑。客户端应按 `entityId` 和 `revision` 幂等应用变更，并保存返回的 `nextCursor`；删除状态同样保留为可拉取的墓碑。

## 旧游标恢复

当服务端无法保证游标之后的删除记录完整时，`sync/pull` 返回 HTTP 409 和 `code=SYNC_RESET_REQUIRED`。`sync/push` 可携带可选的 `cursor`；发生历史清理后，未携带游标或游标过旧的上传同样返回此错误，旧版客户端因此停止同步而不会静默漏掉删除。

新版客户端从 `GET /sync/snapshot` 获取同一数据库快照中的全部未删除任务及游标。应用快照时只替换未排队上传的云端任务；本地待上传的新建、修改、删除与冲突必须保留。云端任务若不在快照中，应在本地标记删除。快照及游标持久化成功后再重试上传；失败则继续使用原游标重试，不清空本地数据。`snapshot.todos` 的项目遵循 `todo.schema.json`。
